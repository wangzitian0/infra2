# 新增服务 SOP (Standard Operating Procedure)

> **用途**：新服务上线的标准检查清单
> **适用对象**：基础设施维护者

---

## 🚀 新服务上线检查清单

### 1. 代码结构验证

确保新服务目录包含以下文件：

| 文件 | 必需 | 用途 |
|------|------|------|
| `compose.yaml` | ✅ | Docker Compose 配置 |
| `deploy.py` | ✅ | Deployer 类 + invoke tasks |
| `shared_tasks.py` | ✅ | status() 健康检查 |
| `vault-agent.hcl` | ✅ | Vault Agent 配置 |
| `secrets.ctmpl` | ✅ | Secrets 模板 |
| `vault-policy.hcl` | ⚠️ | Vault 策略（可选，有默认） |
| `README.md` | ✅ | 服务文档 |

### 2. Vault Secrets 配置

```bash
# 1. 存储服务所需的密钥
invoke env.set <KEY>=<VALUE> --project=<project> --service=<service>

# 2. 生成 AppRole 凭证（role_id/secret_id）
export VAULT_ROOT_TOKEN=$(op read 'op://Infra2/.../Token')
invoke vault.setup-approle

# 3. 验证 VAULT_ROLE_ID/VAULT_SECRET_ID 已写入 Dokploy
# (setup-approle 会自动注入，检查 Dokploy UI 确认)
```

### 3. IaC 集成验证

**仅适用于 `platform` 项目服务** (IaC Runner 管理范围)

```bash
# 验证服务被 discover_services() 发现
python -c "
import sys
sys.path.insert(0, 'libs')
from deploy.deployer import discover_services
services = discover_services()
print('Discovered services:')
for k, v in sorted(services.items()):
    print(f'  {k} -> {v}')
"
```

确保新服务出现在列表中，格式为：
- `platform/<service>` → `<service>.sync` (release tag 推送后由 `reconcile-iac-inputs.yml` 经 `deploy_v2 → IaC Runner` 部署到 staging；prod 显式 promote)
- `finance_report/<service>` → `fr-<service>.sync` (使用应用 CI)
- `bootstrap/<service>` → `<service>.sync` (手动部署)

### 4. 部署验证

```bash
# 部署服务
python -m tools.deploy_v2 --service platform/<service> --type staging --iac-ref vX.Y.Z --domain zitian.party

# 验证健康状态
invoke <service>.status

# 检查容器运行状态
ssh root@$VPS_HOST 'docker ps | grep <container-name>'
```

### 5. 线上健康检查

```bash
# HTTP 健康端点
curl -s https://<subdomain>.zitian.party/health

# 或检查容器健康状态
ssh root@$VPS_HOST 'docker inspect <container> --format "{{.State.Health.Status}}"'
```

### 6. 发布验证（release tag → staging；prod 显式 promote）

**仅适用于 `platform` 项目服务** (IaC Runner 不管理 bootstrap 和应用层)

合并到 `main` **不部署任何东西**（`main` 领先于最新 tag = 未发布）；平台服务随 **release tag** 自动晋升
staging，prod 由人显式 promote。权威定义见 [ops.pipeline.md](../ssot/ops.pipeline.md) §2–3。

1. **IaC Runner 健康检查**
   ```bash
   curl -s https://iac.zitian.party/health
   # 期望: {"status": "healthy", ...}
   ```

2. **PR 阶段预演 fan-out**：PR CI 的「Gate reconcile plan builds」跑 `reconcile --dry-run`，
   summary 应列出 `platform/<service>` 在这次发布会被重部署。合并 PR；此时 GitHub webhook delivery
   （Settings → Webhooks → Recent Deliveries）返回 200 + `{"status":"ignored",...}`——这是正常的，
   `/webhook` 只验签不部署。

3. **打 release tag → 自动 staging**
   ```bash
   git checkout main && git pull
   git tag vX.Y.Z && git push origin vX.Y.Z

   # 观察 reconcile 运行
   gh run list --workflow reconcile-iac-inputs.yml --branch vX.Y.Z --limit 1
   gh run watch <run-id>
   # 期望: 绿；summary 的 selected services 含 platform/<service>，每个服务 sync 终态 succeeded/skipped

   # 观察 IaC Runner 日志
   ssh root@$VPS_HOST "docker logs iac-runner --tail 50"
   # 期望日志: 该 deployment_id 下 "invoke <service>.sync" 的结果；无 failed
   ```

4. **验证 config hash 幂等性**（同一 tag 再跑一次应 no-op）
   ```bash
   python -m tools.deploy_v2 --service platform/<service> --type staging --iac-ref vX.Y.Z --domain zitian.party
   # 期望: config hash 未变 → skipped / no-op（600s 内重复请求还会命中 runner 的 recent-result cache）
   ```

5. **prod（staging soak 后，显式）**
   ```bash
   gh workflow run reconcile-iac-inputs.yml -f after=vX.Y.Z -f promote_prod=true
   # 守卫: tag 必须 reachable from origin/main，且有一次 push 触发的绿色 staging run；成功后记录 production/vX.Y.Z marker
   ```

**注意事项**：
- **Bootstrap 服务** (vault, 1password, iac-runner) 必须手动部署，不走 tag reconcile
- **应用层服务** (finance_report, truealpha) 使用各自的 GitHub CI/CD 经 `deploy_v2` 前门，不经 IaC Runner
- **Platform 服务** (postgres, redis, authentik, etc.) 才随 release tag 经 IaC Runner 部署；fan-out 规则见
  [ops.pipeline.md](../ssot/ops.pipeline.md) §5.2 与 [deploy-dependencies.yaml](../ssot/deploy-dependencies.yaml)

## 📋 快速模板

### deploy.py 模板

```python
import sys
from libs.deploy.deployer import Deployer, make_tasks

shared_tasks = sys.modules.get("platform.XX.new.shared")

class NewDeployer(Deployer):
    service = "new"
    compose_path = "platform/XX.new/compose.yaml"
    data_path = "/data/platform/new"
    secret_key = "password"
    
    # Domain config (set subdomain = None for SSO-protected services)
    subdomain = "new"
    service_port = 8080
    service_name = "server"

if shared_tasks:
    _tasks = make_tasks(NewDeployer, shared_tasks)
    status = _tasks["status"]
    pre_compose = _tasks["pre_compose"]
    composing = _tasks["composing"]
    post_compose = _tasks["post_compose"]
    setup = _tasks["setup"]
    sync = _tasks["sync"]
```

### shared_tasks.py 模板

```python
from invoke import task
from libs.common import check_service

@task
def status(c):
    return check_service(c, "new", "health-cmd")
```

### vault-agent.hcl 模板

> 新服务默认使用 **AppRole** 认证（`role_id` + `secret_id`，由 `invoke vault.setup-approle`
> 注入为 Dokploy env `VAULT_ROLE_ID`/`VAULT_SECRET_ID`，compose entrypoint 落盘到
> `/vault/role_id`、`/vault/secret_id`）。旧的 `token_file`/`VAULT_APP_TOKEN` 周期 token 模型
> 已全面退役（含 IaC Runner，#369；见
> `docs/ssot/bootstrap.iac_runner.md` §6.4）。

```hcl
vault {
  # VAULT_ADDR 来自容器环境变量；未显式指定 address 时 vault-agent 自动读取 VAULT_ADDR。
}

auto_auth {
  method "approle" {
    config = {
      role_id_file_path                   = "/vault/role_id"
      secret_id_file_path                 = "/vault/secret_id"
      remove_secret_id_file_after_reading = false
    }
  }

  sink {
    type = "file"
    config = {
      path = "/vault/.token"
    }
  }

  exit_on_err = true
}

template_config {
  static_secret_render_interval = "5m"
  exit_on_retry_failure = true
}

template {
  source      = "/etc/vault/secrets.ctmpl"
  destination = "/vault/secrets/.env"
  perms       = 0644
}
```
