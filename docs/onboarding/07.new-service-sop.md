# 新增服务 SOP (Standard Operating Procedure)

> **用途**：新服务上线的标准检查清单
> **适用对象**：基础设施维护者

---

## ⚡ 极速上线（Sub-3-Minute Microservice Onboarding，首选推荐）

借助 infra2-sdk 脚手架（`python -m infra2_sdk.scaffold`）与 `service.onboard` 原子事务流水线，新服务上线实现全量自动化，同时保持原有安全与隔离强度（Vault AppRole sidecar、tmpfs 密钥挂载、PostgreSQL 独立限流角色、SigNoz APM）：

### 极速三步法：

1. **脚手架生成规范代码与目录**：
   ```bash
   uv run python -m infra2_sdk.scaffold <service_name> \
     --project <project_name> \
     --port 8000 \
     --template fastapi \
     --db postgres \
     --profile infra2 \
     --out-dir <目标目录>
   ```
   *参数（以 `uv.lock` 锁定的 SDK 版本的 `--help` 为准）：* 位置参数 `name` 是服务名；`--project` 默认 `apps`；`--port` 默认 `8000`；`--template` 取 `fastapi`（默认，目前唯一支持模板）；`--db` 取 `postgres`（默认）或 `none`；`--profile` 取 `infra2`（默认，Dokploy + Vault sidecar）或 `standalone`（纯 12-factor `.env`）；`--out-dir` 默认 `./<name>`。脚手架没有 `--service`、`--domain`、`--with-postgres`、`--with-redis` 参数。

   *`--profile infra2` 的生成产物：*
   - `compose.yaml` (Vault Agent sidecar、显式内存 limits)
   - `Dockerfile`、`entrypoint.sh`、`requirements.txt`
   - `deploy.py` (Deployer 类)
   - `vault-agent.hcl` & `secrets.ctmpl` (AppRole 认证与密钥模板)
   - `app.py` (`--template fastapi`；入口调用 `infra2_sdk.fastapi.init_service`，注册 `/livez`、`/readyz`、`/health` 并按配置启用 OpenTelemetry；`--db postgres` 时附带 PostgreSQL 探针)

2. **执行原子上云 Saga（~15 秒）**：
   ```bash
   invoke service.onboard --service=<service_name> --project=<project_name>
   ```
   *自动化事务动作：*
   - `op` 预检与 1Password 凭据生成/读取（SSOT）
   - PostgreSQL 数据库创建与低特权用户授权（硬限 8 连接，60s idle 超时）
   - Vault KV v2 密文自动同步
   - Vault AppRole 与最小权限 ACL Policy 自动化绑定
   - Dokploy 环境变量注入与验证

3. **部署与上线验证（~60 秒）**：
   ```bash
   python -m tools.deploy_v2 --service <project>/<service> --type staging --iac-ref <tag> --domain zitian.party
   ```

### 🧹 服务下线（Service Offboarding）
```bash
# 锁定数据库角色，终止活跃连接，吊销 AppRole 凭据，保留数据库数据
invoke service.offboard --service=<service_name> --project=<project_name>

# 若需彻底清除数据库（危险操作）：
invoke service.offboard --service=<service_name> --project=<project_name> --purge-data
```

## 🚀 底层契约与手动验证参考（Troubleshooting & Deep Dive）

> 新服务准入与退役的**权威定义**见 [`docs/ssot/ops.service-lifecycle.md`](../ssot/ops.service-lifecycle.md)（`service.onboard` / `service.offboard` 原子 Saga）。以下清单仅在非标服务接入或排障时参考。

### 1. 代码结构契约

确保新服务目录包含以下文件：

| 文件 | 必需 | 用途 |
|------|------|------|
| `compose.yaml` | ✅ | Docker Compose 配置 |
| `deploy.py` | ✅ | Deployer 类 + invoke tasks |
| `shared_tasks.py` | ✅ | status() 健康检查 |
| `vault-agent.hcl` | ✅ | Vault Agent AppRole 配置 |
| `secrets.ctmpl` | ✅ | Secrets 渲染模板 |
| `vault-policy.hcl` | ⚠️ | Vault 策略（可选，有默认） |
| `README.md` | ✅ | 服务文档 |

### 2. Vault Secrets 手动补救（仅非 Saga 路径）

```bash
# 1. 存储服务所需的密钥
invoke env.set <KEY>=<VALUE> --project=<project> --env=<env> --service=<service>

# 2. 生成 AppRole 凭证（role_id/secret_id）并注入 Dokploy
export VAULT_ROOT_TOKEN=$(op read 'op://Infra2/.../Token')
DEPLOY_ENV=<env> invoke vault.setup-approle --project=<project> --service=<service> --deploy
```

### 3. 服务注册与发布验证

- **服务发现**：运行 `python -c "from common.core.registry import service_attrs; print(sorted(service_attrs()))"` 确认服务已被自动发现。
- **Schema 与枚举门禁**（仅限在 `ENUM_SOURCES` 注册的持久化枚举应用）：部署时 `deploy_v2` 会自动通过 `common/deploy/schema_gate.py` 调用 `tools/pre_deploy_schema_check.py`（详情见 [`ops.standards.md` Rule 7](../ssot/ops.standards.md)）。
- **三阶段发布与 fan-out 验证**：合并到 `main` 不触发部署；打 `vX.Y.Z` tag 自动部署 `staging`，`promote_prod=true` 显式晋升 `production`。完整流程与验证步骤见 [`docs/ssot/ops.pipeline.md` §2–3](../ssot/ops.pipeline.md#2-部署目标与触发-deploy-targets--triggers)。
- **跨目录构建依赖**：若服务镜像打包了 `common/**` 或 `tools/**`，须在 [`docs/ssot/deploy-dependencies.yaml`](../ssot/deploy-dependencies.yaml) 登记。
