# Canary Todo (Infrastructure Verification Tool)

Canary service at `todo.zitian.party` (with per-slot domains `todo-<slot>.zitian.party` declared in `platform/30.todo/slots.yaml`: `v4-11`, `v4-13`, `v4-14`). It proves the platform's real runtime paths. The full contract is in [`docs/ssot/platform.canary_todo.md`](../../docs/ssot/platform.canary_todo.md).

## Overview

- **Service**: todo (multi-slot: `todo-v4-11`, `todo-v4-13`, `todo-v4-14` via `slots.yaml`)
- **Port**: 8000 (container) -> 443 (Traefik)
- **Subdomain**: per-slot routes (`todo-<slot>.zitian.party`, plus primary `todo.zitian.party`) using Authentik ForwardAuth proxy labels in `compose.yaml`
- **Deployer**: `TodoDeployer` (`platform/30.todo/deploy.py`)
- **Watchdog Probes**: per-slot `ProbeFacet`s (`todo-canary-status` for the primary slot and `todo-<slot>-canary-status` for secondary slots) polling `/api/canary/status` over the Docker network

## Validated Capabilities

1. **Redis** (`platform/02.redis`): `AUTH`, then `SETEX`, `GET` and `DEL` of a random value under per-slot `REDIS_KEY_PREFIX`. `-NOAUTH` fails.
2. **Postgres** (`platform/01.postgres`): isolated per-slot roles and databases (`todo_v4_11_app`/`todo_v4_11`, `todo_v4_13_app`/`todo_v4_13`, `todo_v4_14_app`/`todo_v4_14`, plus `todo_app`/`postgres`), `SET LOCAL transaction_read_only = off` first, then `SELECT 1`, and a session-scoped `canary_todo_probe` temporary table `CREATE`/`INSERT`/`SELECT`/`DELETE` roundtrip. `TodoDeployer` and `preview.compose.yaml` also ensure native enum `canary_todo_capability` matches `canary_schema:METADATA` (`schema_check`). An `E` reply fails.
3. **S3** (`platform/03.s3`): `PUT`, `GET` and `DELETE` of one object under per-slot `S3_KEY_PREFIX` (`canary/v4-11/`, `canary/v4-13/`, `canary/v4-14/`) in bucket `platform-canary`.
4. **SigNoz** (`platform/11.signoz`): collector liveness. The canary also exports its own traces, logs, and custom OpenTelemetry metrics (`canary.probe.duration_ms`, `canary.probe.outcomes`), with its SigNoz v5 dashboard in `dashboard.json`.
5. **OpenPanel** (`platform/24.openpanel`): API liveness via `OPENPANEL_HEALTH_URL`, plus `openpanel` and `browser_otel` capability env vars via `TodoDeployer.compose_env_base`.
6. **Authentik** (`platform/10.authentik`): SSO liveness.
7. **Startup, Worker & Runtime Governance**:
   - `env.manifest.json`: enforced fail-closed at startup via `validate_startup_environment()` (`assert_env`).
   - `worker.py`: proves `worker_run()` and `request_with_retry` (`canary.worker.tick` span).
   - `runtime-hooks.manifest.json`: 5-slot runtime verification hooks (`smoke`, `preview_gate`, `staging_gate`, `prod_gate`, `scheduled_audit`); `staging_gate` and `prod_gate` run `probe_health.py --gate`.
   - `compose.yaml` is an `x-infra2` source (#1822 Slice 2) using all four `x-capabilities` (`s3`, `otel`, `openpanel`, `browser_otel`), with `preview.compose.yaml` mirroring them for Preview parity. The compiled `vault-agent` sidecar holds its config and template inline and labels them `infra2.vault.config.sha256` and `infra2.vault.template.sha256`. `CONFIGURATION_SHA256` hashes the compiled text, so a template change recreates the sidecar. The deploy renders the template from `env.manifest.json`; git holds no `secrets.ctmpl` or `vault-agent.hcl` here. `vault-policy.hcl` is committed and generated by `tools/secrets_render.py --write`.

## Endpoints

- **Health (public)**: `GET /api/health` returns HTTP 200 JSON including release identity fields `version` and `git_sha`.
- **Canary status (internal)**: `GET /api/canary/status` returns the check matrix. Each check is `pass`, `fail` or `unconfigured` (a missing credential). Only Redis, Postgres and S3 gate the HTTP status. SigNoz, OpenPanel and Authentik are informational. The probe runner reads it over the Docker network. SSO users reach it through the protected router. It is not public.
- **Web UI (SSO)**: `GET /` is protected by Authentik ForwardAuth.

## Deploy

```bash
# once per environment, staging first (see the SSOT doc, section 4)
DEPLOY_ENV=<env> uv run invoke vault.setup-approle --project=platform --service=todo
DEPLOY_ENV=<env> uv run invoke todo.sync
DEPLOY_ENV=<env> uv run invoke todo.sso-setup
```
